# ns-3 即时入队无效轮询修复说明

日期：2026-11-01
适用后端：`ns3_ext/tgax-control.cc`（交互式训练与评估后端）

## 1. 问题背景

当前 MAC-CMDP 正式配置使用：

```text
traffic_mode = mac-arrival
direct_high_watermark = 0
direct_admission_poll_us = 500
```

`direct_high_watermark=0` 的既定语义是“即时原生 MAC 入队”：业务到达后，
`Generate()` 直接调用 ns-3 `WifiMac::Enqueue()`，不经过应用层 pending 队列和水位门控。

修改前，`MacArrivalApplication::StartApplication()` 无论水位值是否为 0，都会为每条业务流启动
一次 `AdmissionTick()`；该回调平均每 500 微秒执行一次并继续调度自身。即时入队模式下
`m_pending` 永远不会接收数据，所以这些回调只会查询空队列、生成一个轮询随机数并再次调度，
不会改变任何数据包或 MAC 状态。

当前实验共有 206 条业务流，因此无效回调的理论量级为：

```text
206 flows × (1 / 500 us) ≈ 412,000 callbacks / simulated second
```

仅 100 个正式训练 step 就约有 4,120 万次无效回调；scaler 和 held-out 评估还会继续增加。

## 2. 修改内容

本次只修改 `ns3_ext/tgax-control.cc`：

1. `StartApplication()` 仅在 `m_highWatermark > 0` 时创建 admission poll 事件；
2. `AdmissionTick()` 增加 `m_highWatermark == 0` 的入口保护，防止未来其他调用路径重新引入轮询；
3. 保留 `m_highWatermark > 0` 的历史水位模式，调度频率和行为不变；
4. 增加源码级回归测试，锁定即时入队模式不得启动轮询的约束。

未修改以下内容：

- Cost 与 Reward 公式、预算和拉格朗日乘子；
- 业务模型、业务随机数流和 seed；
- EDCA 动作空间与 CW 更新；
- 原生 `WifiMacQueue` 容量、寿命、重传和丢弃行为；
- Spectrum/Yans PHY 实现；
- 批量后端 `tgax-s3.cc`。该后端使用非零的 64 包水位，轮询是有效逻辑，不能删除。

轮询使用独立的 `m_pollUniform` 随机数流；即时模式下停止抽取该流不会改变业务模型使用的
`m_uniform`、`m_exponential` 等随机数流。

## 3. 固定 seed A/B 验证

测试条件：

| 项目 | 值 |
|---|---:|
| seed | 9902 |
| PHY | Spectrum |
| STA | 40 |
| 业务流 | 206 |
| 控制窗口 | 0.2 simulated seconds |
| 动作 | Default/native BEB |
| traffic warm-up | 0（单独隔离被测 step） |

结果：

| 指标 | 修改前 | 修改后 | 结论 |
|---|---:|---:|---|
| 后端启动耗时 | 6.732 s | 6.767 s | 基本一致 |
| 0.2 秒 step 耗时 | 75.747 s | 74.030 s | 降低 2.27% |
| Reward | 0.4182799987 | 0.4182799987 | 完全一致 |
| Utility | 0.5659842663 | 0.5659842663 | 完全一致 |
| QoS Cost | 0.4770426759 | 0.4770426759 | 完全一致 |
| Starvation Cost | 1.0 | 1.0 | 完全一致 |
| 生成字节（四个 AC） | 完全一致 | 完全一致 | 通过 |
| 接收字节（四个 AC） | 完全一致 | 完全一致 | 通过 |

短基准的加速比为 1.023 倍。结果说明无效事件风暴已消除且实验输出保持确定性，但也说明它不是
当前长耗时的唯一主因。40 STA Spectrum PHY、逐包 PHY/MAC 事件、CW 逐次落盘，以及 ns-3 到
Python 的逐事件传输仍占据主要运行时间。

原始 A/B 数据保存在本地忽略目录：

```text

results/benchmarks/admission_poll_after_seed9902/benchmark_summary.json
```

## 4. 验证项目

- `tests/test_mac_cmdp_experiment_entry.py`：增加即时入队不启动轮询的回归约束；
- 重新编译 ns-3.44 `tgax-control`，构建类型为 `RelWithDebInfo`（`-O2 -DNDEBUG`）；
- 固定 seed 真实 Spectrum ns-3 A/B 测试；
- 对比 Reward、Utility、Cost、生成字节和接收字节，全部完全一致。

补充限制：Windows/MinGW 构建出的 ns-3 `test-runner` 在执行 `wifi-txop` suite 时以
`0xC0000005`（访问冲突）退出且未产生 suite 输出；`--help` 和测试列表查询正常。
因此本次不能把该 suite 计为通过。应用层调度修复的集成结论以成功完成的真实 Spectrum
固定 seed A/B 仿真为准，Python 回归测试用于防止条件分支回退。

## 5. 训练恢复说明

发现问题时正在运行的对照实验已在 scaler 预跑阶段安全停止，尚未进入正式梯度更新。
旧的未完成输出予以保留，不覆盖、不作为最终实验结果。

由于训练 checkpoint 的 `source_hash` 包含 `ns3_ext/tgax-control.cc`，修改后不能把旧 checkpoint
当作同一代码版本继续训练；应使用重新编译后的二进制从新的独立输出目录开始运行。

## 6. 后续性能工作建议

按预期收益和研究风险排序：

1. 为训练模式关闭不参与状态或 Reward 计算的 `cw_runtime.csv` 逐次记录，并做输出等价验证；
2. 将每包 `Y` 事件的 Cost 所需统计量在 C++ 侧聚合，减少 stdout、Python 对象创建和多遍扫描；
3. 用相同 seed 比较 Spectrum 与 Yans 的速度和指标差异，仅在确认科研结论不变后考虑训练代理；
4. 多 seed 实验使用进程级并行；单个 ns-3 离散事件仿真本身仍主要使用单核。
