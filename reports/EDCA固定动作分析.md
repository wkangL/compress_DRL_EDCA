# EDCA 固定动作分析

## 1. 目的与实验控制

本阶段先回答“v2 业务中是否存在可利用的 EDCA 优化空间”。如果代表性固定动作都不能改善默认 EDCA，继续训练 DDQN 的意义有限；如果固定动作能形成稳定权衡，而 DDQN 学不到，则应检查奖励与训练覆盖。

实验固定 ns-3 后端、v2 五场景、队列、retry limit=7、队列寿命 10 s、统计 schema 3 和业务随机逻辑，只改变一个固定 `ControlAction`。动作在整个 warmup 和测量窗口内不变，没有按场景在线切换。

粗扫包含 12 个动作、5 个场景、2 个 seed，共 120 次；每次 10 s 预热、15 s 测量。复核选 Default、P8、P10、P13，使用 3 个新 seed（651–653）、10 s 预热和 20 s 测量，共 60 次。所有比例先按 seed 计算，再报告跨 seed 均值和 95% t 区间。

## 2. 代表动作

| 动作 | 主要参数含义 | 选择原因 |
|---|---|---|
| Default/P0 + BEB | 标准 802.11a EDCA；VO `3/7`、VI `7/15`、BE/BK `15/1023` CWmin/max | 基线 |
| P8 + BEB | VO/VI TXOP 均为 6.016 ms；BE/BK CWmin 31/63 | 强化实时 TXOP |
| P10 + BEB | VO/VI CWmin 15/31；BE/BK CWmin 31/63 | 较均衡的保守竞争 |
| P13 + BEB | VO/VI CWmin 31/31；BE/BK CWmin 63/127 | 大 CW、显著减少碰撞 |

粗扫还覆盖 P1、P3、P6、P15，以及 P0/P3 下 1.2、1.6、2.4 倍自定义 CW 增长。自定义 1.2 倍在 S2/S4/S5 一致降低交付率，例如 S2 约从 97.2% 降到 90.7%，说明竞争失败后过慢扩大 CW 会维持高碰撞。P15 虽降低 VO 时延，却在 BE 主导 S3 将总交付率降到约 90.1%，因此不能作为通用实时优化。

## 3. 三 seed 复核结果

### S1：默认 EDCA 已很好

Default 总交付 99.999%，VO/VI p95 为 0.665/1.123 ms。P8 的总 goodput 基本不变，外部碰撞率由 0.0645 降至 0.0514，VO/VI p95 降至 0.620/1.023 ms。绝对改进只有 0.046/0.100 ms，业务意义有限。

P10/P13 虽进一步降低碰撞，却把 VO p95 提高到 1.079/1.222 ms，VI p95 提高到 1.859/1.547 ms。它们仍远低于 20/50 ms 目标，但证明“大 CW 在轻载下会增加不必要的接入等待”。后续 Reward 必须保留低负载时延保护，不能只奖励低碰撞。

### S2：P13 显示明确优化余量

| 指标 | Default | P8 | P10 | P13 |
|---|---:|---:|---:|---:|
| Goodput (Mbit/s) | 13.888 | 14.002 | 14.283 | **14.283** |
| 外部碰撞率 | 0.425 | 0.394 | 0.149 | **0.094** |
| 总交付率 | 97.51% | 98.08% | 99.99% | **99.99%** |
| VO按时完成 | 97.78% | 98.27% | 99.93% | **99.96%** |
| VI按时完成 | 96.90% | 97.55% | 99.97% | **99.98%** |
| BE/BK交付 | 95.51% / 99.23% | 97.33% / 99.30% | 99.98% / 100% | **99.98% / 99.96%** |
| VO/VI p95 (ms) | 6.135 / 11.886 | 5.361 / 10.522 | 4.752 / 9.531 | **4.080 / 5.793** |

P13 相对 Default：goodput 增加约 2.84%，外部碰撞率降低约 77.9%，VO/VI p95 降低约 33.5%/51.3%，且没有以 BE/BK 服务退化交换这些收益。三个 seed 方向一致，因此 S2 存在真实且较大的固定动作优化空间。

### S3：默认已接近满交付，P8 只有小幅时延收益

Default 总交付 99.988%，VO/VI p95 为 0.901/1.636 ms。P8 将外部碰撞率降低约 29.7%，VO/VI p95 降低约 16.4%/18.9%，但 goodput 和交付率几乎不变。P10/P13 把实时时延增加到 2–4 ms，仍无吞吐收益。

所以 S3 的可优化量主要是很小的接入时延与碰撞能耗代理，并非业务交付能力。不能用相对百分比夸大亚毫秒级变化。

### S4：存在两类 Pareto 权衡

| 指标 | Default | P8 | P10 | P13 |
|---|---:|---:|---:|---:|
| Goodput (Mbit/s) | 16.305 | 16.580 | **17.881** | 17.523 |
| 外部碰撞率 | 0.345 | 0.297 | 0.193 | **0.110** |
| 总交付率 | 94.66% | 95.43% | **99.18%** | 98.03% |
| 最终失败率 | 4.15% | 3.25% | **0.01%** | 1.28% |
| BE/BK交付 | 75.86% / 85.76% | 79.70% / 81.74% | **98.90%** / 82.77% | 89.02% / **99.88%** |
| VO/VI p95 (ms) | 3.436 / 6.960 | **2.845 / 5.633** | 6.705 / 13.559 | 4.239 / 6.065 |

P8 偏向降低实时尾部；P10 偏向总交付和 BE，但增加 VO/VI 排队时延且没有改善 BK；P13 显著降低碰撞并平衡提升 BE/BK，VI p95 略优于 Default，但 VO p95 增加约 23.4%（绝对增加 0.803 ms）。CCDF 还显示 P13 的极尾部更长：VO/VI p99 为 8.47/12.62 ms，高于 Default 的 5.75/11.53 ms；P8 的 p99 则降至 4.99/9.49 ms。S4 没有单一指标上的“万能最好动作”，P8、P10、P13 构成可解释的权衡集合。

### S5：P13 对动态负载仍保持优势

Default 总交付 98.76%，外部碰撞率 0.368，VO/VI p95 为 5.047/9.967 ms。P13 分别为 99.98%、0.086、3.730/5.420 ms：goodput 增加约 1.17%，碰撞率降低约 76.5%，VO/VI p95 降低约 26.1%/45.6%。P10 总交付略高于 P13 的均值，但 VI p95 为 8.303 ms，且 P13 的最终失败均值为 0。

这说明 S5 的状态切换并没有消除固定大 CW 的收益，但固定 P13 无法根据低/高状态主动改变动作。S5 仍适合检验 1 s 时序和异步报告是否能让学习策略在 P8/P10/P13 之间随状态选择。

## 4. 对 DDQN 和 Reward-v2 的约束

1. 动作空间确实包含明显优于默认的区域，尤其是 S2/S4/S5；因此后续 DDQN 有可学习目标。
2. 仅奖励低碰撞会倾向 P13，并在 S1/S3 引入不必要的接入等待。Reward-v2 需要显式保护 VO/VI 时延或按时完成率。
3. 仅奖励总交付会倾向 S4 的 P10，但可能增加实时尾部并使 BK 无明显改善。BE/BK 需要分 AC 服务保障，而不是只用总 goodput。
4. 固定动作的“每场景最佳”依赖仿真器已知场景标签，不能作为部署算法。它们只用于离线上界、下界和动作敏感性参考。
5. 后续训练的动作覆盖至少应包含 P8、P10、P13；若策略在 S2/S4/S5 从不选择这些区域，应先检查探索和奖励，而不是增加训练预算。

## 5. 可靠性与局限

- 粗扫使用 2 seed，95% t 区间会很宽，只用于筛选；主要结论来自 3 个全新 seed 的复核。
- 复核每个 case 只有 20 s 测量，适合阶段 E 的方向判断，不替代最终 5+ 训练 seed 和固定测试 seed。
- “按时完成”仍使用阶段 D 的窗口下界定义；Reward-v2 必须先完成逐包 deadline ledger，才能用于训练。
- P13 在 S2/S5 的优势跨 3 seed 一致；S1/S3 的绝对时延差很小，不据此宣称显著业务提升。
