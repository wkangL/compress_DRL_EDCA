结论：现有 quick 结果存在真实的时延退化，尤其 S3 的 BE；当前证据不能支持完整方案全面优于默认 EDCA，也不能用 reward 上升或 TD loss 下降代替时延改善。训练量不足和奖励目标偏差同时存在，继续训练不保证解决后者。

## 奖励机制与动作证据

`rl/reward.py`、`configs/default.yaml` 的实际定义：

- 吞吐项为按业务加权的交付吞吐/提供负载比例，权重 1.5。
- VO/VI 时延项分别为 `clip(max(p95/threshold - 1, 0), 0, 2)`，阈值 20/50 ms，权重 0.8/0.6。低于阈值的退化没有直接时延惩罚，超过阈值三倍后惩罚饱和。
- BE/BK 时延没有直接奖励项；窗口内 p95 也不能完整约束更深尾部。
- 碰撞、丢弃、公平性、动作变化另有惩罚，故模型可能通过减碰撞提高 reward，同时延长等待。

实测核对了两方案全部 240 个 quick 评估决策窗口：只有 1 个窗口出现 VO/VI 时延惩罚（完整方案 seed 1、S2 的 VI）。其余 239 个窗口的两个时延惩罚均为零；S3 全部为零。BE/BK 时延恶化本身不会触发该惩罚。

S3 的 reward 改变量分解（使用 evaluation.csv 中窗口奖励分项，不能拿整段碰撞率替代）：碰撞项 +0.03136141，吞吐项 -0.00451209，动作变化项 -0.00376000，丢弃项 +0.00001047，公平性项 -0.00000523，两个时延项均为 0，总计 +0.02309456。即使 BE p95 明显变坏，这套目标仍给出更高分。

动作日志支持“竞争更保守”的解释，但尚不是因果证明：S3 Default 的 20 个窗口均为 profile 0（BE CWmin=15）；完整方案 seed 1 的 20 个窗口主要 profile 5（16 个，BE CWmin=63），seed 2 主要 profile 13（15 个，BE CWmin=63），另有 profile 15（4 个，BE CWmin=255）。profile 同时改变多项 EDCA 参数，alpha/beta/gamma 也会变化；要归因到具体参数，仍需固定动作对照实验。

## 后续实验顺序

1. 保留原奖励正式续训作为可复现对照，观察第 42/44 阶段及之后的独立评估；不在中途换奖励，否则历史 replay、Q 目标和实验口径混杂。
2. 单独设计奖励消融：让各 AC 的时延退化进入连续代价，并对实时业务超阈值另加约束；预先明确吞吐与时延的取舍，不根据最终测试结果调权。
3. 固定高频 profile 与默认动作做对照，区分动作空间本身的取舍、学习未稳定和观测压缩影响；所有方案使用相同预算和评估种子。
4. 使用独立监测集选择配置；保留测试集做最终确认。报告各 AC 的 CCDF、吞吐、丢弃及多训练 seed 波动，不以 reward 或 TD loss 单独判定成功。
