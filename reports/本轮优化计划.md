## 2. 阶段与准入条件

### 阶段 A：统计链路与数据守恒核查

1. 归档当前代码、配置、依赖、正式检查点、训练日志、原始事件、汇总表和图。
2. 按 STA、AC、方向核对：生成、入队、队列拒绝、ACK 成功、TTL 过期、达到重试上限、其他终止和仿真结束未完成。
3. 验证逐包唯一终态以及生成包守恒，先运行 S2/S4 的两个种子，再扩展到全部场景。
4. 统一 offered、accepted、attempt、success 和各类 loss 的分母；拆分外部碰撞、内部争用、PHY 接收失败、ACK timeout 和 RTS 相关失败。
5. 补齐 UL/DL/AC goodput、时延均值/p95/p99/CCDF、按时送达率、迟到成功率、最终失败率和队列统计。
6. 明确 Jain 指数的对象与时间尺度，并输出每 STA、每 AC 的分布及业务满足率。

准入条件：逐包守恒、统计边界测试、重放一致性和两种子核查全部通过后，才允许开始新的正式 DDQN 训练。

阶段产物：`reports/指标统计正确性核查.md`，以及独立审计脚本、测试和带统计 schema 的结果目录。

### 阶段 B：AP 可观测状态审计

逐项标注状态来源、采样窗口、AP 是否可观测、是否重复。重点检查全网成功事件、全局公平性、真实到达率等“上帝视角”量，以及 recent/current 的重复。默认候选局部全局状态为：信道 busy 比例 1 维、四 AC UL goodput 4 维、AP 四 AC 下行队列 4 维、关联 STA 数 1 维；反馈 age/coverage 只保留在聚合器中。

阶段产物：`reports/AP可观测状态审计.md`。

### 阶段 C：DDQN 稳定性核查

补充 online/target Q、TD target、TD error、Q 标准差、target 同步前后损失、独立评估 reward、replay 场景/动作覆盖率。验证完整 target 网络独立且冻结；修复 time-limit truncated 被当作真实 terminal 的问题。通过小规模诊断比较 hard update 500 与 soft update `tau=0.005/0.001`，不把诊断运行混入正式结论。

阶段产物：`reports/DDQN训练稳定性分析.md`。

### 阶段 D：场景重新标定

保留 S2/S4 作为压力场景，以负载扫描建立轻载、典型中载、拥塞和动态负载场景。参考标准和论文时，记录可复核来源、业务模型和映射依据。

阶段产物：`reports/场景流量重新设计.md`。

### 阶段 E：固定动作结构优化

先在统一统计口径下扫描固定 EDCA/反馈动作，以多种子评估代表性配置，为强化学习提供可解释上界、下界和动作敏感性。

阶段产物：`reports/固定动作结构优化.md`。

### 阶段 F：Reward v2

以按时送达和有效传输为核心，候选形式为：

`R2 = 1.0 U + 0.8 ontimeVO + 1.0 ontimeVI - 0.3 collision - 0.3 drop - 0.2 fairness - 0.02 action_change`

实现前先固定 on-time 的边界归属、无样本区间行为和低优先级保护项。若状态或 reward 维度、语义发生变化，建立新检查点，不继续加载旧模型。

阶段产物：`reports/Reward重新设计.md`。

### 阶段 G：受控优化与阶段 H：多种子正式对比

一次只改变一个机制，先完成消融和短诊断，再用多个训练种子、独立评估种子比较六种方法。时延统一画 CCDF；另输出只含 baseline 与 Compressed Async + Age 的图和带提升/降低百分比的表格。

阶段产物：`reports/受控优化实验.md`、`reports/最终多种子对比.md`。
