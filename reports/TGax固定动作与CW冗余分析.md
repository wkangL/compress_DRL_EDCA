# TGax固定动作与CW冗余分析

日期：2026-10-25  
场景：`candidate_voip8_gaming4_ftp_bk`，7 个同信道 BSS、每 BSS 40 STA；仅 BSS0 的 AP 与 40 STA 接受控制。  
范围：固定动作机制核验和 CW 动作冗余分析；未运行 DDQN，未修改 Reward、业务、队列或无线参数。

## 1. 实验设计与正确性

四组固定动作如下。自定义 CW 统一使用 `alpha=2, beta1=1.6, beta2=2.8, gamma=6`。

| 组别 | EDCA | CW增长 | 实际动作索引 | 含义 |
|---|---|---|---|---|
| A | P0 | ns-3 原生 BEB | `[0,0,5,5,2]`，`custom=false` | 标准 Baseline |
| B | P0 | 自定义 | `[0,1,3,9,1]`，`custom=true` | 只改变 CW 增长 |
| C | P8 | ns-3 原生 BEB | `[8,0,5,5,2]`，`custom=false` | 只改变 EDCA Profile |
| D | P8 | 自定义 | `[8,1,3,9,1]`，`custom=true` | P8 上再改变 CW 增长 |

P0 是标准 EDCA。P8 保持 VO/VI 的 AIFSN、CWmin、CWmax，但把 VO/VI TXOP 都改为 6.016 ms，并把 BE/BK CWmin 分别改为 31/63。参数来自 [`configs/profiles.json`](../configs/profiles.json)。

正式实验使用 seed 41；因四组呈现出有意义且相互制约的差异，又用独立 seed 42 做方向复核。每次包含 2 s 关联预热、1 s 统一业务预热、20 个连续 1 s STEP 和 1 s 排空。固定动作只在测量开始时应用一次，后续 STEP 不重复重置 EDCA/CW。实现见 [`scripts/run_tgax_fixed_actions.py`](../scripts/run_tgax_fixed_actions.py) 和 [`ns3_ext/tgax-control.cc`](../ns3_ext/tgax-control.cc)。

两种子的审计均通过：

- 四组在每个 STEP 的外生应用需求逐字节一致；
- 280/280 STA 正确关联；
- BSS1–6 的 EDCA 始终为 Default，非默认记录数为 0；
- A 在测量窗开始没有伪动作重置；B/C/D 只在开始时变化一次；
- MAC 账本满足 `期初未完成 + 新入队 = 成功 + 最终失败 + 期末未完成`。

### 2.3 B 相对 A：只修改 CW 增长

- Reward 在 seed 41/42 分别提高 **1.6%/6.6%**，Jain 公平性提高 **18.8%/17.0%**。
- VO 及时率却分别降低 **6.7%/3.1%**。seed 41 的 DL-VO p95 从 15.73 ms 增至 42.49 ms；seed 42 则从 90.13 ms 降至 79.27 ms，方向不稳定。
- VI 重传在多数方向下降，尤其 DL-VI；吞吐也可能显著增加。但 TCP 流在拥塞下存在启动、阻塞和竞争放大，两种子中的吞吐增幅差别很大，不能据此宣称稳定增益。
- 因而该 CW 规则确实改变了 MAC 行为，并能提高综合 Reward/公平性；它没有形成一致的 VO/VI 尾时延收益，且会牺牲 VO 及时性。

### 2.4 C 相对 A：只修改 EDCA Profile

- seed 41 的 Reward 降低 3.3%，四个 VO/VI p95 均变差；seed 42 的 Reward 提高 5.0%，四个 p95 均改善。
- P8 的效果显著依赖具体随机业务和 TCP 状态。它增加 VO/VI TXOP，同时增大 BE/BK CWmin，造成上下行和 AC 之间的容量重新分配；当前两个种子不足以证明 P8 稳定优于 P0。

### 2.5 D 相对 C：P8 上增加自定义 CW

- Reward 在 seed 41/42 分别降低 **5.1%/5.3%**。
- VO 及时率分别降低 8.7%/4.3%，VI 及时率降低 1.0%/2.1%。
- 两个种子的 UL/DL、VO/VI 四个 p95 全部变差。例如 UL-VO 分别增加 27.7% 和 29.2%。
- 这是本轮最稳定的方向性证据：当前自定义 CW 参数与 P8 组合没有额外收益。

### 2.6 BE/BK与TCP解释限制

HTTP/FTP 的真实 TCP 栈均运行，应用层有建立连接和交付记录；TCP 反向纯 ACK 主要进入 BE，这与当前实现和 ns-3 的 IP 优先级映射一致。FTP 数据 socket 设置 `0x20`，对应 QoS UP1/AC_BK。

但 FTP 文件主要在统一的 1 s 业务预热内开始传输，随后进入平均约 180 s 的阅读间隔。正式 20 s 测量窗内 BSS0 的 BK 成功 MPDU 为 0 或仅 1 个，多个组合没有 BK 到达。故：

- BK 无样本时，时延、丢包率和重传率记为未定义，不能记为 0；
- 应用层 FTP 交付只证明协议和映射链路活着，不代表正式测量窗内 BK 获得了服务；
- BE 也有若干组合仅个位数至几十个成功样本，其低 p95 不应解释为改善；
- 本轮结果不足以评价 BK 控制收益。后续若要让 BK 进入 Reward，应先解决测量窗覆盖，而不是调 Reward 掩盖无样本问题。

完整绝对数值、样本数和配对变化见 [`combined_metrics.csv`](../results/summary/tgax_fixed_actions_2seed_20261025/combined_metrics.csv)、[`paired_effects.csv`](../results/summary/tgax_fixed_actions_2seed_20261025/paired_effects.csv) 与 [`application_delivery.csv`](../results/summary/tgax_fixed_actions_2seed_20261025/application_delivery.csv)。

## 3. CW增长轨迹与动作冗余

### 3.1 实际公式

对第 `r` 次失败：

`CW(r)=min(CWmax, ceil(beta*(CW(r-1)+1))-1)`

其中 `r<=alpha` 使用 `beta1`，之后使用 `beta2`；只在 `r<=gamma` 时更新，之后保持。分析采用当前实际重试上限 10。原生 BEB 独立于该公式，必须显式关闭 `custom_growth`。

![选定动作CW轨迹](../results/figures/tgax_fixed_actions_2seed_20261025/selected_cw_trajectories.png)

例如 P0 下原生 BEB 的 BE/BK 轨迹为 `15,31,63,127,255,511,1023...`，当前自定义轨迹为 `15,25,41,117,330,926,1023...`。VO/VI 因 CWmax 很小，前 1–3 次失败即大量饱和，后续 beta2/gamma 很难再产生区别。

每个 Profile 有 459 个合法 `(alpha,beta1,beta2,gamma)` 组合；“不同轨迹”按四个 AC、0–10 次失败的 CW 序列完全相同来判定。

## 4. 建议的精简动作设计

本轮只提出方案，不修改动作空间或网络。

1. **保守候选，便于现有代码迁移**：保留 16 个 Profile；取 `alpha={1,2,3}`、`beta1={1.6,2.0}`、`beta2={2.0,2.4,2.8}`、`gamma={5,6,7}`，共 `16×54=864` 个自定义组合，再加 1 个原生 Default 回退，共 **865** 个。它保留本轮测试的 `(2,1.6,2.8,6)`。
2. **严格去重候选**：按每个 Profile 的四 AC 完整 CW 轨迹预计算代表动作，只留 241 个自定义轨迹，再加原生 Default 回退，共 **242** 个联合动作。该方案去重最彻底，但更适合把动作改成“联合候选表”，不再维持五分支的独立笛卡尔积语义。
3. 前 3 次重传的近似去重暂不用于正式动作删除，因为少量高重传包仍会看到后续轨迹差异。

当前五分支训练不能选择真正的 `Default EDCA + 原生BEB`：训练路径总是以 `custom=true` 执行动作，P0 只代表默认 EDCA 参数。最小改法是在现有合法组合中保留一个哨兵元组，后端将该元组解码为 `P0 + custom=false`，无需改变 Q 网络输出维度；下一次正式修改网络时，再把 CW 模式显式设为 `native/custom` 会更清楚。

## 5. 对下一版DDQN的具体建议

1. 先加入可选择的原生 Default 回退，并删除数学完全等价动作，避免多个 Q 分支索引学习同一 MAC 行为。
2. 不要把当前固定自定义 CW 当作“已证实优于 BEB”。B 对 A 只有综合 Reward/公平性方向一致，VO 及时性方向一致地下降；D 对 C 则稳定退化。
3. 在恢复训练前，让正式测量窗内确实出现 BE/BK 业务样本，否则低优先级惩罚主要反映“无到达/长阅读间隔”，无法教会控制器如何服务 BK。
4. 保留逐 MPDU 样本数、未定义值和 CCDF；Reward、吞吐或少样本 p95 均不能单独作为策略有效证据。
5. 下一轮小训练应同时报告相对 A 的配对结果，并把“VO/VI及时率不退化”和“BE/BK有足够风险样本”设为进入多 seed 训练前的验收条件。

## 6. 最终回答

**CW增长规则有没有可验证的性能收益？** 机制生效已经得到验证，P0 上它在两个种子都提高了 Reward 和公平性，也降低了部分 VI 重传；但 VO 及时率在两个种子都下降，尾时延收益不一致。在 P8 上，它在两个种子均降低 Reward、及时率并恶化全部 VO/VI p95。因此当前参数没有可宣称的稳定综合性能收益。

**7344种动作是否大量冗余？** 是。按实际公式、4 AC 和完整重试上限严格计算，7344 个合法动作中 3898 个与同 Profile 的其他动作产生完全相同轨迹，完全重复比例 **53.08%**。可先缩为易实现的 865 个候选；若改为按轨迹代表动作的联合表，可缩到 242 个，同时保留独立原生 Default 回退。
