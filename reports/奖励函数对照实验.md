# 奖励函数对照实验

更新时间：2026-10-21

## 结论边界

本阶段比较 Reward-v1、Reward-v2 和 Reward-v2 + 低优先级服务保障。三组保持状态、网络、动作、soft target、流量、预算、训练 seed 和独立评估 seed 一致，只改变奖励。每组仅 1 个训练 seed 的 quick 筛查，不能据此宣称收敛或统计显著。现有证据支持将 Reward-v2 带入下一阶段的 3-seed 中等预算；当前服务保障项暂不并入主配置。

## 因果期限记账

VO/VI 期限分别为 20/50 ms。分母只包含当前决策边界前已经得到完整判决的包：期限前 ACK 或丢弃时立即判决；仍未完成的包在期限到达时形成失败判决；迟到 ACK 不改写判决；未到期限且仍在队列中的包不进入分母。

ns-3 STEP 协议升到 schema 4，逐节点、逐 AC 输出 `deadline_eligible` 和 `on_time_delivered`。原生测试逐 UID 从 `OFFERED/ACKED/DROP` 轨迹复算，和后端完全一致。源码变化后重做容量标定：`C_ref=27.30225 Mbit/s`，54/81 Mbit/s 高负载点均值为 27.2785/27.3260 Mbit/s。

## 奖励定义

Reward-v1 原样保留：

`R1 = 1.5U - 0.5C - 0.5D - 0.8P_VO - 0.6P_VI - 0.2F - 0.02A`

Reward-v2：

`R2 = 1.0U + 0.8O_VO + 1.0O_VI - 0.3C - 0.3D - 0.2F - 0.02A`

`O_VO/O_VI` 为因果期限内交付率。v2 的丢包项采用精确记账的 `final_failure_fraction`。尚无成熟判决时及时率项无效并记 0，不把未成熟包当失败。

服务保障消融额外增加 `-0.5 × mean(max(0, 0.9-Service_BE/BK))`，仅对当前活跃的 BE/BK 生效。

## 预算

- 方法：Compressed Async + Age；训练 seed 11；独立监控 seed 301。
- S1–S5；6 stages × 4 episodes × 5 s，共 120 次决策交互。
- 第 2–6 阶段共 500 次梯度更新；soft target `tau=0.001`。
- 阶段 1、2、4、6 做独立 greedy 评估；最终表取阶段 6。

v1 在阶段 1 评估后因旧绘图代码写死四场景而中断。checkpoint 已完整保存；脚本改成动态布局后精确续跑。失败目录保留，没有重跑或删除该阶段数据。

## 结果解释

- S2：v2 相对 v1 将碰撞率降低 25.5%、VI p95 降低 6.4%、BE 满足度略有恢复；VO p95 增加 16.4%。两者及时率均接近 1，quick 样本已接近饱和。
- S4：v2 相对 v1 将碰撞率和 VI p95 均降低约 35.5%、VO p95 降低 14.2%；代价是吞吐降低 1.6%，BE 满足度由 0.968 降至 0.921。相对 Default，v2 的 VI p95 改善 9.4%、碰撞改善 66.4%、丢包降为 0、BE 满足度由 0.829 提至 0.921；VO p95 则恶化 25.7%。
- S5：v2 相对 v1 将碰撞降低 11.7%，VO/VI p95 降低 6.8%/7.5%，BE/BK 满足度保持为 1。
- 服务保障项在 S4 把 BE 满足度从 0.921 恢复到 0.947，但相对纯 v2，碰撞增加 25.8%、VI p95 增加 11.5%，当前权重没有形成更好的总体折中。
- S1/S3 的 Default 时延本来极低。v2 的 S1 VO/VI p95 从 0.648/1.107 ms 增至 1.256/1.515 ms，S3 从 0.879/1.797 ms 增至 1.939/2.534 ms。绝对值仍低，但这是明确的低负载退化。

## 训练诊断

三组 TD loss 均有限。首/末 100 次更新平均 TD loss：v1 为 0.1517/0.00289，v2 为 0.5820/0.00268，v2+保障为 0.5792/0.00440。v2 奖励尺度更大，不可把不同奖励的 Q 值或 loss 绝对值横向解释为优劣。loss 下降也不能证明策略收敛。

## 下一阶段

主候选采用 Reward-v2，不加入当前服务保障项。Stage G 保持网络、soft target 和业务不变，做 3 个独立训练 seed 的中等预算。重点检查 S2/S4/S5 的 VI 及时率与 CCDF、S4 BE 满足度，以及 S1/S3 低负载退化是否跨 seed 稳定。若 BE 退化稳定出现，再单独调整服务保障权重，不能同时修改学习率、target 或网络结构。

Stage G 已按上述设置完成。三个训练 seed 的阶段 20 结果支持 Reward-v2 的重载收益具有重复性，同时确认低负载时延退化也具有重复性；S4 BE 满足度均值为 0.928，未出现灾难性饥饿。Q 公共基线仍随持续任务的正回报上升，因此只判定策略评估趋稳，不判定价值函数收敛。详细诊断见 `reports/DDQN训练稳定性分析.md`。
