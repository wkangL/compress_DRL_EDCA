# 丢包记账修复与验证（2026-10-19）

已修复生产后端的拒绝入队漏记、STEP 末尾过期回调遗漏及非整采样周期的统计缺口。主实验寿命保持 10 秒、重试上限保持 7；队列限额、流量、EDCA 参数均未修改。历史训练与结果保留。

## 根因与实现

1. ns-3.44 的 `WifiMacQueue::DoEnqueue` 在 scheduler 判断必须拒绝当前包时直接返回 false，绕过了基类的 `DropBeforeEnqueue`，导致队列统计和 `DroppedMpdu` 通知均缺失。新增 `ns3_ext/queue_drop_trace.patch` 在该分支恢复通知，不修改接受/拒绝决策。
2. 过期包从队列移除后，其 Expired 回调由 ScheduleNow 执行。原采样立即输出并清零计数，末尾 STOP 可能抢在这些回调之前。现先清理过期，再在同一时刻输出采样；STEP 返回前处理同刻回调并核对守恒，不延长仿真时间。
3. 新增 `READY 2` 协议和 `P` 区间账本。每个节点、每个 AC 单独统计，并验证：**期初在队 + 本期生成 = 本期成功 + 溢出 + 过期 + 重试耗尽 + 其他丢弃 + 期末在队**。仅统计带 MeasurementTag 的业务包，在队计数来自原生 Enqueue/Dequeue 通知；截止时仍在队的包不算丢失。守恒失败会中止运行，不能静默产出结果。
4. Python 汇总优先使用 P 精确计数，包含不足一个采样周期的区间。S 保留用于状态反馈，避免重复累计。整轮评估计数求和、队列取首尾快照，校验相邻区间连续性，并以 D 成功事件核对交付包数/字节数。

P 字段顺序：time, node, AC, offered, ACKed, overflow, expired, retry-drop, other-drop, pending-start, pending-end, offered-bytes, ACKed-bytes, retry-attempts, attempts, timeouts。除首尾队列快照外均为本 STEP 的增量。
