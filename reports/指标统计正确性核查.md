# 指标统计正确性核查

更新时间：2026-10-20（Asia/Shanghai）

## 结论

阶段 A 的严格核查已通过：S1–S4 各两个种子（101、102），每次 10 秒业务预热加 60 秒测量，逐包验证 80 个 STA×AC×方向分组。每个包最多一个终态；测量窗口均满足 `期初在途 + 窗口生成 = ACK + 各类最终失败 + 期末未完成`；窗口生成包还满足 `成功入队 + 同步拒绝入队 = 生成`。观察器只增加 CSV trace，短程生产/观察器 stdout 完全一致，生产二进制哈希未改变。

逐包核查与历史 baseline schema 2 的 256 个共同 AC 计数字段全部逐项相等；本轮生产账本为 schema 3。代码指纹为 `eb16eea9ef7eb8638bcb557a2fcff833f39592ba731f9b51eaa946ac7ebb2ea4`。

这表示现有 baseline 的 offered、ACK、overflow、expiry、retry-limit、other 和 pending 计数正确；但现有汇总中的 `drop_rate` 分母只用窗口内 generated，分子可能含期初积压在窗口内失败的包。后续正式表统一使用 `final_failure_fraction = 最终失败 / (期初在途 + 窗口生成)`，并单列 `queue_rejection_fraction_of_generated`、`unfinished_fraction` 和 `delivery_fraction`。旧字段保留用于历史复现。

## 统一口径

- generated：测量窗口内创建并交给 Wi-Fi 设备的 MAC 业务包。accepted：实际触发 MAC queue Enqueue；queue rejected：同步 FailedEnqueue。
- ACK success：AckedMpdu；expiry：ExpiredLifetime；retry final：ReachedRetryLimit；other：其余 DroppedMpdu 原因；unfinished：测量结束仍未出现终态。
- goodput：测量窗口内 AckedMpdu 的业务 payload bit / 60 s，按 UL、DL、AC 和 STA 都可拆分。
- delay：创建时间到 AckedMpdu 的时间，仅对成功包定义；失败和 unfinished 不塞入成功时延分布，而在 on-time、late success、final failure、unfinished 中单列。
- VO deadline 暂按 20 ms、VI 按 50 ms，用 `created <= end-deadline` 的包作为 on-time 分母，避免右删失伪装为超时。
- external collision：目标接收端 PHY drop，且该 PSDU 在空口区间内检测到重叠发送；分母为相同 AC/方向的实际 DATA attempts。other PHY failure 与 ACK/CTS timeout 分列。主场景 RTS/CTS 关闭，因此 RTS 计数为 0。
- internal collision：同一设备多个 EDCAF 同时到期、输掉虚拟碰撞的事件。schema 3 在 `FrameExchangeManager::NotifyInternalCollision` 更新重试/CW 前触发只读 trace；它与 external collision 分列，组合事件比例使用 `(external+internal)/(DATA attempts+internal)`。

S2 VI 的几百毫秒尾部由高竞争下的反复退避/timeout和队列等待共同形成；它不是把失败包赋成低时延的统计假象。方向拆分 CCDF 位于审计图目录。队列统计表给出每节点/AC 的 mean、p95、max 和 nonempty fraction；AP 的 DL 是共享 AC 队列，不能伪造成每目的 STA 的独立 DL 队列。

## Jain 与业务满足率

Jain 同时输出全业务每 STA goodput及每 AC 每 STA goodput，时间尺度为完整 60 秒测量窗口。`fairness_and_satisfaction.csv` 另给 VO/VI 每 STA 的按时率最小值和中位数。现有 reward 使用的总 goodput Jain 不能代表 VO/VI 分别公平，也不能代表各 STA 是否满足时限。
