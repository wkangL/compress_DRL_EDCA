STA本地MAC时序状态
→ STA侧TCN压缩
→ 压缩报告随STA已有上行发送机会主动捎带

→ 输出EDCA Profile + CW增长参数
→ 作用于整个BSS
→ 网络运行产生下一阶段状态和奖励

==================================================
三、第0阶段：先验证EDCA，不允许直接开始训练AI
==================================================

正式训练TCN/DDQN之前，必须先证明EDCA环境基本正确。

主实验默认场景：

- 单BSS；
- 1 AP；
- 10 STA；
- 单碰撞域；
- 所有STA彼此可载波侦听；
- 无隐藏节点；
- ACK开启；
- RTS/CTS关闭；
- 第一阶段关闭A-MPDU/Block Ack，优先采用普通DATA/ACK过程；
- PHY链路设置为高可靠，不人为引入随机PHY误码；
- 因此第一阶段的Retry主要来自竞争和碰撞；
- 四个AC均存在独立EDCAF和独立MAC队列。

必须检查：

AIFS：
信道忙时退避必须冻结；
信道重新空闲并满足对应AIFS后才能恢复。

CW：
每个AC独立维护CW和backoff；
成功/失败后的更新必须符合相应规则。

内部碰撞：
同一个STA中多个AC同时结束退避时，必须执行EDCA virtual/internal collision逻辑，而不是随机任选一个。

ACK：
单播数据成功应收到ACK；
ACK超时应进入重传流程。

Retry：
一次失败后继续尝试计入Retry。

Failed：
达到retry limit后最终失败。

Discarded：
本地队列超时或其他队列侧丢弃必须与Failed区分。

TXOP：
必须是真正的TXOP时长限制，不能只作为一个标签。

请至少自动运行以下EDCA sanity check：

1）单STA、低负载：
碰撞率应接近0。

2）STA数量增加：
竞争和碰撞应总体增加。

3）不同AC：
VO/VI应整体比BE/BK获得更低接入时延。

4）增大CWmin：
碰撞应下降，但平均接入等待应上升。

5）RTS/CTS：
开启以后应真实出现RTS→CTS→DATA→ACK过程。

6）隐藏节点：
建立A组和B组STA。
两组均可被AP正常接收，但A、B彼此无法载波侦听。
RTS/CTS关闭时碰撞应明显恶化。
RTS/CTS开启后性能应得到一定程度恢复。

7）CW增长：
当自定义增长规则设置成与标准BEB等效的参数时，其统计行为应接近标准BEB。

只有这些检查通过以后，才能继续AI实验。

把结果写进：
reports/EDCA仿真正确性检查.md

内容必须说明：
- 检查了什么；
- 理论上应该出现什么现象；
- 实际结果是什么；
- 是否通过；
- 若未通过，原因是什么。

==================================================
四、STA侧状态定义
==================================================

STA本地按照AC分别维护MAC状态历史。

四个AC：
- AC_VO
- AC_VI
- AC_BE
- AC_BK

默认采样周期：

ΔSTA = 100 ms

默认历史窗口：

WSTA = 1 s

因此每个AC保存最近10个采样点。

每个100 ms采样点包含：

1. Queue Size
当前100 ms结束时该AC队列中的字节数。

2. Average Access Delay
当前100 ms内成功完成接入/发送的数据包对应MAC接入时延均值。

若该100 ms内没有有效Access Delay样本：
Delay设为0；
同时Validity设为0。

3. Retry Count
当前100 ms内新增的重传次数。
使用区间增量，不使用历史累计计数。

4. Failed Count
当前100 ms内达到retry limit后最终失败的数量。
使用区间增量。

5. Discarded Count
当前100 ms内由于本地队列原因丢弃的数量。
使用区间增量。

6. Delay Validity
有有效Delay样本为1，否则为0。

因此：

X_i,c ∈ R^(10×6)

不得把Retry/Failed/Discarded换成从仿真开始不断累积的总计数。

预处理：

Queue：
log1p后标准化。

Delay：
截断极端异常值后log1p，再标准化。

Retry/Failed/Discarded：
log1p后标准化。

Validity：
保持0/1。

Scaler只能由训练数据确定，评估集不得重新计算。

32

3

1、2、4

最后：
时间维池化 + Linear

==================================================
六、TCN究竟如何训练
==================================================

这一点严格按照下面逻辑实现。

研究目标是：
TCN + AP信息汇聚 + DDQN共同服务最终控制任务。

TCN不是各STA自行在线训练。

训练阶段：
在中心仿真训练环境中联合优化。

部署阶段：
训练完成后，把同一版本Encoder部署到所有增强STA；
AP部署汇聚网络和DDQN；
正常运行期间模型固定。

如果后续重新训练Encoder，应理解为一次新的模型版本整体更新，而不是不同STA各自变化。

为避免同一个episode里不同STA使用不同版本Encoder：

一个episode运行期间Encoder参数冻结。

Encoder只能在统一同步点更新。

建议做法：

- 一个训练阶段包含若干episode；
- 在该阶段内所有STA使用同一Encoder版本；
- 收集replay数据；
- 在阶段结束后允许更新Encoder；
- 更新完成后所有STA同时切换新版本；
- 清空或重新初始化AP中上一版本的压缩报告缓存；
- 必要时清理与旧表示强绑定的replay数据。

代码中显式维护：

encoder_version

禁止出现：
STA1用version 3，
STA2仍然用version 2，
而AP直接把两个latent混在一起。

Replay Buffer中尽量保存生成报告时对应的原始历史窗口快照及时间信息，而不是只保存最终latent，以方便训练时进行表示学习。

TCN主要由DDQN的TD loss提供任务导向梯度。

如果训练过程中发现latent明显塌缩，例如多个维度长期方差接近0，再启用一个很轻量的辅助loss。

辅助任务只预测该历史窗口中的：
- Queue末值；
- Delay均值；
- Retry总量；
- Failed总量；
- Discarded总量。

辅助loss权重初始设为0.05。

除非确实发现训练不稳定，否则不要让辅助loss主导模型。

==================================================
七、主动报告机制
==================================================

STA并不是固定每100 ms向AP发送报告。

100 ms只是本地采样周期。

实际报告采用“主动捎带”逻辑：

STA只有在自己真正获得上行发送机会，而且上行数据帧成功发送给AP时，才能刷新AP侧压缩报告。

默认最小报告间隔：

T_report_min = 100 ms

如果一个TXOP中连续发送多个MPDU，只允许第一个满足条件的帧更新压缩报告，避免重复上报。

当报告生成时：

STA使用报告生成时刻之前最近1 s历史窗口计算：

z_i,c(t_report)

AP收到后缓存：

latest_report[i][c]
report_time[i]
encoder_version[i]

在AP决策时刻t：

age_i = t - report_time[i]

如果某个STA从未成功上报：
valid_i = 0

否则：
valid_i = 1

报告age由AP计算，不要求STA额外上报。

注意：
不得在决策时偷偷使用STA当前真实状态替代缓存中的旧报告。

Compressed Async实验必须严格使用：
“AP最后一次真正收到的报告”。

==================================================
八、AP侧本地统计
==================================================

AP不能只依赖STA压缩报告。

AP还需要保留自身能够直接观测的全网状态。

AP本地统计可以每100 ms更新一次，但不代表每100 ms执行一次DDQN。

默认同时维护：

最近1 s统计；
当前决策周期整体统计。

至少包含：

1. Channel Busy Ratio
2. Collision / ACK Timeout Ratio
3. Total Goodput
4. Jain Fairness
5. Active STA Ratio
6. 各AC的AP可观测Goodput
7. AP侧下行队列状态（如果该场景存在下行业务）
8. 全STA Report Age均值
9. Report Age P95
10. 有有效报告的STA比例

如果发现部分指标高度重复，可在后续消融中精简，但第一版先保留。

==================================================
九、AP如何汇聚不同STA的压缩报告
==================================================

不要把：

STA1 latent | STA2 latent | ... | STA10 latent

直接按STA编号拼接。

因为最终动作并不区分STA，而是针对整个BSS和四类AC。

按AC分别汇聚。

对于AC c，AP当前缓存：

(z_1,c, age_1, valid_1)
(z_2,c, age_2, valid_2)
...
(z_N,c, age_N, valid_N)

每一个STA首先经过共享的小MLP：

输入：
8维latent
+ normalized report age
+ valid flag

输出：
32维STA表示。

然后使用简单的“STA信息汇聚模块”。

不要使用很复杂的Transformer。

优先采用：
单头attention pooling

同时保留一个max pooling分支以避免某个非常紧急STA被平均掉。

最终每个AC形成：

attention pooled feature
+
max pooled feature
+
mean report age
+
P95 report age
+
valid coverage

得到AC级状态C_c。

四个AC：

C_VO
C_VI
C_BE
C_BK

汇聚操作必须对STA编号置换不敏感。

STA1和STA5交换编号，不应该显著改变同一组状态对应的模型输入。

==================================================
十四、CW增长规则
==================================================

采用四个共享参数：

α
β1
β2
γ

候选集合：

α ∈ {1, 2, 3}

β1 ∈ {
1.0,
1.2,
1.4,
1.6,
1.8,
2.0
}

β2 ∈ {
1.0,
1.2,
1.4,
1.6,
1.8,
2.0,
2.2,
2.4,
2.6,
2.8,
3.0
}

γ ∈ {5, 6, 7}

要求：

β2 >= β1

不满足条件的Branching DDQN动作必须使用action mask禁止。

设一次失败后的重传阶段为n：

1 <= n <= α：
使用β1增长；

α < n <= γ：
使用β2增长；

n > γ：
CW保持γ阶段对应值，不继续增长。

CW更新：

CW_new =
min(
CWmax,
ceil( β × (CW_old + 1) ) - 1
)

成功传输后：
恢复CWmin。

当β1=β2=2，并且不提前进入饱和阶段时，应能够近似退化为传统BEB。

该退化关系必须加入自动测试。

==================================================
十六、Reward
==================================================

Reward必须尽量使用比例、速率和归一化指标，使1 s、5 s、10 s决策周期之间具有可比性。

不要直接使用“一个决策周期内总包数量”作为reward主体。

首先计算每个活跃AC的吞吐满足度：

u_c =
clip(

0,
1
)

VO = 1.2
VI = 1.1
BE = 1.0
BK = 0.5

Throughput Score：

U =
Σ(w_c × u_c)
/
Σ(active w_c)

如果某AC当前没有业务，则不参与分母。

定义QoS违例：

VO阈值：
20 ms

VI阈值：
50 ms

d_vo =
clip(
max(0, p95_VO / 20ms - 1),
0,
2
)

d_vi =
clip(
max(0, p95_VI / 50ms - 1),
0,
2
)

若当前周期无对应VO/VI数据包：
该delay penalty记为0，并记录valid flag。

碰撞：

c =
clip(collision_rate, 0, 1)

丢包：

l =
clip(drop_rate, 0, 1)

公平性：

f =
1 - Jain_Fairness

动作变化惩罚：

s =
normalized_action_change

==================================================
十八、核心对比实验
==================================================

最重要的实验不是“TCN重构准确率”。

核心比较如下。

A. Default EDCA

无AI动态控制。

B. Full-State Fresh

AP每次决策都直接获得各STA最新完整1 s时序状态。

这是信息充分情况下的近似控制性能上界。

C. Raw Async

STA仍然只能在真实上行成功发送机会到来时报告。

但是不压缩，直接向AP提供完整历史状态。

用于研究：
仅异步/陈旧信息造成多少损失。

D. Compressed Fresh

使用TCN压缩。

但假设每个决策时刻所有STA均有最新报告。

用于研究：
仅压缩造成多少损失。

E. Compressed Async No-Age

使用TCN；
采用真实主动捎带；
AP不知道report age。

F. Compressed Async + Age

完整方案：

TCN
+
真实主动捎带
+
AP显式使用report age
+
STA信息汇聚
+
DDQN。

核心关系：

Full-State Fresh
vs
Compressed Fresh

回答：
压缩本身带来的控制性能损失。

Compressed Fresh
vs
Compressed Async

回答：
异步主动报告带来的陈旧性损失。

Compressed Async No-Age
vs
Compressed Async + Age

回答：
显式使用报告时效性是否有帮助。

Raw Async
vs
Compressed Async + Age

回答：
相同真实上报时机下，压缩信息相对于完整信息的控制性能差异。

二十四、运行效率
==================================================

当前环境可能主要使用CPU，EDCA事件仿真通常是主要耗时来源。

因此：

- 网络模型保持轻量；
- 不使用大型Transformer；
- 多seed和独立场景优先采用进程级并行；
- 不要在每个MAC事件都调用Python神经网络；

- 统计信息增量维护；
- 避免反复扫描所有历史packet记录。

优先优化接口和减少跨语言调用次数。

不得为了加速直接删除ACK、退避冻结、内部碰撞等关键MAC过程。
